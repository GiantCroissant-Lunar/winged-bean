## Why the Desktop Window Was Not Showing Initially
- MonoGame/SDL on macOS requires the game loop to run on the **main thread**.
- Top-level `await` makes the entry point an async Main, which moves continuations off the main thread.
- Fixes applied:
  - Removed top-level `await` in `Program.cs` and used `GetAwaiter().GetResult()` to keep execution on main thread.
  - Removed background `Task.Run` around `_game.Run()` in `SadConsoleApp`.
  - Started host synchronously, then resolved `IUIApp` and invoked the UI entry blocking call on the main thread.

## Build & Run
- **Build artifacts**
  - Console: `_artifacts/<version>/dotnet/console/bin/`
  - Desktop: `_artifacts/<version>/dotnet/desktop/bin/`

  ```bash
  task build-dotnet
  ```

- **Run Desktop from artifacts (macOS)**

- **Run Console from artifacts**


## Notable Code Paths
- **Desktop host**: `development/dotnet/windows/src/host/Dungeon.Host.SadConsole/Program.cs`
  - Build host, start synchronously, then resolve `IUIApp` and run on main thread.
- **Plugin Loader**: `development/dotnet/windows/src/host/Dungeon.Host.SadConsole/PluginLoaderHostedService.cs`
  - Loads plugin assemblies from `plugins/`, sets registry, activates plugin, registers services.
- **SadConsole plugin**: `development/dotnet/windows/src/plugins/WingedBean.Plugins.SadConsole/SadConsolePlugin.cs`
  - Implements `IPlugin`. In `OnActivateAsync`, registers the UI app service in the registry.
- **SadConsole app**: `development/dotnet/windows/src/plugins/WingedBean.Plugins.SadConsole/SadConsoleApp.cs`
  - Creates the SadConsole `Game`, wires `GameHost.Instance.Screen`, then runs the game loop on main thread.
- **Copy dependencies**: `WingedBean.Plugins.SadConsole.csproj`
  - `<CopyLocalLockFileAssemblies>true</CopyLocalLockFileAssemblies>` ensures SadConsole dependencies are copied for plugin loading.

## Known Limitations / Notes
- **MonoGame on macOS**: Must keep UI calls on main thread; avoid top-level `await`. If you alter the host startup, keep this constraint.
- **FNA vs MonoGame**: FNA package isn’t available via NuGet in this repo; MonoGame DesktopGL works and is retained.
- **Registry vs DI**: The plugin registers `IUIApp` in the registry for `Program.cs` to resolve; DI alone isn’t sufficient for this flow.
- **Artifacts**: `.gitignore` updated to avoid tracking `build/_artifacts/` and generated docs.

## Quick Troubleshooting
- **Window does not open (macOS)**
  - Confirm running from artifacts: `./build/_artifacts/latest/dotnet/desktop/bin/Dungeon.Host.SadConsole`
  - Ensure no top-level `await` reintroduced in `Program.cs`.
  - Confirm SadConsole `Game.Create` and `_game.Run()` are on main thread (see `SadConsoleApp.cs`).
- **Plugin not loading**
  - Check `plugins/` in desktop bin contains `WingedBean.Plugins.SadConsole.dll` and SadConsole deps.
  - Verify registry registration in `SadConsolePlugin.cs`.
